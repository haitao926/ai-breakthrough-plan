# 🦅 项目经理 (PM) 黑话指南

**核心奥义**：**对抗熵增**。
**第一性原理**：世界上的一切事物（包括这个项目），如果不加干预，都会自然而然地走向混乱（熵增）。项目经理就是那个注入能量、维持秩序、让团队形成合力的“负熵人”。

---

### 1. 里程碑 (Milestone)
*   **黑话定义**：游戏存档点。
*   **第一性原理**：**时间是线性的，但人的注意力是发散的。**
    如果目标太远（比如“造长城”），人会感到绝望。我们将巨大的时间跨度切分成若干个小段，每到一个节点就进行一次“状态确认”，这符合人类大脑的奖励机制。
*   **怎么做**：把大目标拆解，并在日历上画圈：“周五前必须把[上传功能]做完”，这就是一个存档点。

### 2. MVP (最小可行性产品)
*   **黑话定义**：能跑的破车。
*   **第一性原理**：**进化论与资源稀缺。**
    自然界的生物不是生下来就完美的，而是先活下来（可用），再进化（迭代）。在资源（时间和精力）有限的情况下，与其造一个完美的轮子，不如先造一个能滚动的圆木。
*   **怎么做**：砍需求！问自己：“去掉这个功能，它还能解决最核心的问题吗？”如果能，就先不做这个功能。

### 3. 需求池 (Backlog)
*   **黑话定义**：愿望清单。
*   **第一性原理**：**有限的处理能力 vs 无限的想法。**
    人的想法是无限的，但执行力是有限的。我们需要一个缓冲区（Buffer）来存放那些“将来可能做”的事情，从而保护当前的专注力不被打断。
*   **怎么做**：不要脑子一热就去写代码。先把所有想做的功能记在一个小本子上，按优先级排队。

### 4. 迭代 (Iteration)
*   **黑话定义**：版本升级。
*   **第一性原理**：**反馈循环 (Feedback Loop)。**
    谁也无法通过一次预测就击中移动的靶子。最科学的方法是：先射出一箭 -> 观察偏了多少 -> 调整角度 -> 再射一箭。这就是迭代。
*   **怎么做**：V0.1（能用） -> 听取反馈 -> V0.2（好看） -> 听取反馈 -> V0.3（好用）。

### 5. 站会 (Stand-up)
*   **黑话定义**：对齐。
*   **第一性原理**：**信息同步的成本。**
    团队协作最大的损耗来自“信息不对称”（我以为你做了，其实你没做）。站会就是一种高频、低成本的信息同步协议，用来消除这种不对称。
*   **怎么做**：每天开始工作前，用 1 分钟回答三个问题：昨天做了什么？今天打算做什么？有什么困难？
