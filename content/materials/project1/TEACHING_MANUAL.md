# 项目1：体感互动游戏 (Vibe Coding) - 教师授课指南 (Teaching Manual)

## 📅 课程概览
*   **课程名称**：Vibe Coding - AI 时代的体感游戏开发
*   **课时安排**：4 课时（每课时 45 分钟）
*   **适用对象**：零基础或 Python 入门学生
*   **核心目标**：学生能使用 AI 辅助编写代码，完成一个基于 MediaPipe 的 Web 端体感游戏。

---

## 🎒 课前准备 (通用)
*   **软件环境**：
    *   浏览器（Chrome/Edge）
    *   代码编辑器（VS Code 或 Cursor - 推荐）
    *   Node.js 环境（可选，如果使用本地服务器）
    *   Python (用于简单 HTTP server: `python -m http.server`)
*   **硬件设备**：带有摄像头的笔记本电脑或台式机。
*   **素材包**：`course-files/project1/` 下的素材（如有）。

## 📝 第1课：视觉引擎启动 (Vision Bootcamp)

### 🎯 教学目标
1.  理解计算机视觉（CV）的基本原理：图像 -> 关键点坐标。
2.  体验 AI 代码辅助工具（Cursor/ChatGPT）。
3.  **产出**：一个能在网页上实时显示手部骨架的 Demo。

### ⏱️ 教学流程 (45分钟)

#### 0-5分钟：引入与钩子 (Hook)
*   **动作**：展示一个酷炫的体感控制视频（如 Minority Report 电影片段或 Xbox Kinect 游戏）。
*   **话术**：
    > "同学们，你们玩过 Just Dance 吗？或者用过抖音/Snapchat 的特效滤镜？它们是怎么知道你的脸在哪里的？今天，我们不只需要‘玩’，我们要亲手‘造’一个这样的系统。而且，我们不需要像以前那样写几千行代码，因为我们有 AI 助手。"

#### 5-15分钟：核心概念 (Concept)
*   **知识点**：MediaPipe 关键点检测。
*   **讲解逻辑**：
    1.  电脑看到的不是"手"，是一堆像素。
    2.  AI 模型（MediaPipe）把像素变成了 21 个坐标点 (Landmarks)。
    3.  每个点都有 (x, y, z)，范围是 0.0 到 1.0（归一化坐标）。
*   **板书/PPT**：画一个手掌，标出 0号点（手腕）、8号点（食指指尖）。

#### 15-40分钟：实战演练 (Hands-on)
*   **任务 1：搭建环境 (10min)**
    *   让学生新建文件夹 `hand-tracking`。
    *   新建 `index.html`。
    *   **AI 提示词**："请帮我生成一个基于 MediaPipe Hands 的最简单的 HTML 示例代码，能够调用摄像头并在画布上画出手部骨架。"
*   **任务 2：运行与调试 (10min)**
    *   使用 Live Server 或 `python -m http.server` 运行。
    *   **关键问题**：很多学生直接双击打开 html，导致摄像头权限被拒绝。
    *   **解决方案**：必须强调使用 `http://` 协议（本地服务器）。
*   **任务 3：探索坐标 (5min)**
    *   修改代码：`console.log(landmarks[8].y)`。
    *   观察：手举高时 y 是变大还是变小？（注意：Web 中 y 轴向下是正方向，所以举高 y 变小）。

#### 40-45分钟：总结与预告 (Wrap-up)
*   **提问**："如果我想用食指当鼠标，我该读取哪个点的坐标？"
*   **预告**："下节课，我们用 AI 写一个真正的游戏引擎。"

## 📝 第2课：游戏架构搭建 (Game Logic)

### 🎯 教学目标
1.  理解游戏循环 (Game Loop) 的概念。
2.  使用 Prompt Engineering 生成 Phaser.js 游戏原型。
3.  **产出**：一个键盘控制的简易游戏（跑酷或接东西）。

### ⏱️ 教学流程 (45分钟)

#### 0-5分钟：回顾与引入
*   **回顾**：上节课我们拿到了手的坐标。
*   **引入**：光有坐标没用，得有游戏给它控制。今天我们用 30 分钟写出一个游戏。

#### 5-15分钟：Prompt Engineering 教学
*   **原理**：AI 是一个超级实习生，你必须把任务说清楚。
*   **示范**：
    *   ❌ 差评 Prompt："帮我写个游戏。"
    *   ✅ 好评 Prompt："请使用 Phaser.js 框架写一个简单的横版跑酷游戏。背景是黑色，主角是一个红色方块，会自动向右跑。按下空格键时主角跳跃。地面上有随机出现的绿色障碍物，碰到障碍物游戏结束。"

#### 15-40分钟：实战演练
*   **任务 1：生成游戏代码 (15min)**
    *   学生尝试编写 Prompt，发给 AI。
    *   将生成的代码放入 `game.js` 或直接在 `index.html` 中运行。
*   **任务 2：阅读与修改 (10min)**
    *   引导学生找到控制**跳跃高度**的变量（如 `jumpVelocity` 或 `gravity`）。
    *   挑战：让主角跳得更高，或者跑得更快。
*   **任务 3：理解核心函数 (5min)**
    *   讲解 `preload()` (加载图片), `create()` (生成对象), `update()` (每一帧运行)。
    *   强调：`update()` 函数每秒运行 60 次，我们的控制逻辑要写在这里。

#### 40-45分钟：总结
*   **展示**：选几个修改得比较有趣的（比如跳得飞高的）展示。
*   **预告**："现在是按空格跳，下节课我们要把‘按空格’变成‘动鼻子’。"

## 📝 第3课：核心交互融合 (Integration)

### 🎯 教学目标
1.  将 MediaPipe (CV) 与 Phaser.js (Game) 结合。
2.  处理异步数据与游戏帧率的同步问题。
3.  **产出**：可以用身体（如跳跃、挥手）控制的游戏。

### ⏱️ 教学流程 (45分钟)

#### 0-5分钟：逻辑拆解
*   **问题**：怎么把第1课的代码和第2课的代码连起来？
*   **逻辑**：
    1.  MediaPipe 每一帧算出 `nose.y`。
    2.  如果 `nose.y < 0.5` (人跳起来了/头抬高了)。
    3.  触发游戏的 `player.jump()`。

#### 5-15分钟：缝合代码 (Stitching)
*   **演示**：
    *   把 MediaPipe 的 `<script>` 引用加到游戏 HTML 里。
    *   把摄像头初始化的代码放到 `create()` 之前。
    *   定义一个全局变量 `let isJumping = false;` 来传递信号。

#### 15-40分钟：实战演练
*   **任务 1：移植摄像头代码 (10min)**
    *   确保游戏背景里（或角落里）能看到摄像头画面（方便调试）。
*   **任务 2：编写触发逻辑 (15min)**
    *   在 `onResults` 函数里：
        ```javascript
        if (landmarks[0].y < 0.4) { // 阈值需要调试
            game_player.jump();
        }
        ```
    *   **难点**：阈值（Threshold）设置。每个人离摄像头距离不同，0.4 不一定准。
*   **任务 3：调试阈值 (Debug) (5min)**
    *   使用 `console.log(landmarks[0].y)` 观察自己站着和跳起时的数值变化，找到分界线。

#### 40-45分钟：总结
*   **体验**：全班起立，对着摄像头试玩。
*   **预告**："能玩了，但界面太丑，字太小。下节课我们要把它变成科技节的展品。"

## 📝 第4课：产品化与发布 (Product Launch)

### 🎯 教学目标
1.  优化用户体验 (UX)：大屏适配、引导提示。
2.  代码重构与清理。
3.  **产出**：完成度高、适合在大屏幕展示的作品。

### ⏱️ 教学流程 (45分钟)

#### 0-10分钟：产品思维 (UX Design)
*   **场景模拟**：想象这是学校科技节，大屏幕放在大厅，周围很吵。
*   **需求列表**：
    1.  **字要大**：分数要巨大，霓虹特效。
    2.  **无需键盘**：游戏结束后，能不能挥手重开？（Restart by Wave）。
    3.  **防误触**：路人经过怎么办？（设置识别区域 ROI）。

#### 10-30分钟：极速优化 (Polishing)
*   **任务 1：视觉升级 (10min)**
    *   用 AI 生成酷炫的背景图、粒子特效代码。
    *   Prompt: "Add a particle trail effect to the player."
*   **任务 2：逻辑完善 (10min)**
    *   增加“挥手开始游戏”的状态机。
    *   Game States: `IDLE` (等待) -> `PLAYING` (游戏中) -> `GAME_OVER` (结算)。

#### 30-45分钟：发布会 (Showcase)
*   **形式**：Demo Day。
*   **流程**：
    *   每组派代表上台演示。
    *   其他同学作为“投资人”进行点评。
*   **结语**：
    > "恭喜大家！你们不再只是玩家，你们是创造者。这只是开始，接下来的课程我们将去设计更复杂的产品。"

## 🛠️ 常见问题 (Troubleshooting)

1.  **摄像头黑屏/无反应**
    *   **检查**：浏览器是否允许了摄像头权限？
    *   **检查**：是否使用了 `file://` 打开？必须用 `http://` (Local Server)。
    *   **检查**：是否有其他程序（如腾讯会议）占用了摄像头？

2.  **人物乱跳/控制不灵**
    *   **原因**：光线太暗，MediaPipe 识别不准。
    *   **原因**：阈值设置不合理。
    *   **解决**：调整光线，或打印坐标值重新设定阈值。

3.  **AI 生成的代码报错**
    *   **策略**：把报错信息（Console Error）完整复制给 AI，问它："There is an error: [Error Message], please fix it."
