# 3. 设计原则 (Design Principles)

**版本**: v1.0
**状态**: 初稿

## 1. 核心设计哲学

本平台的设计应始终围绕一个核心——**将复杂的科创项目流程，转化为清晰、可执行、有成就感的游戏化任务**。我们设计的不是一个呆板的管理工具，而是一个能激发学生探索欲和创造力的“练级地图”。

- **真实性 (Authenticity)**: 所有功能都应服务于解决校园内的真实痛点，让学生感受到“我做的东西真的有用”。例如，“校园3D打印商店”就是一个连接了真实需求、真实技术和真实商业模式的优秀案例。
- **闭环 (Closed-loop)**: 功能设计必须形成闭环，让学生的每一个规划和设计都能在后续流程中得到实现和验证。例如，产品规划的PRD和Figma原型，必须是下一阶段全栈开发的核心输入。
- **成就感 (Accomplishment)**: 平台应提供明确的“成果”展示，无论是可交互的原型、可运行的应用，还是最终的路演PPT，都应能方便地分享和“炫耀”，成为学生的“社交货币”。

## 2. 用户驱动的开发流程 (User-Driven Process)

平台的功能开发，应遵循从“产品经理”课程中提炼出的用户驱动思想，完整地覆盖“调研->设计->规划->验证”的流程。

1.  **🔍 侦探模式 (Research)**
    - **原则**: 先理解问题，再谈解决方案。平台在规划新功能时，应通过访谈、问卷等形式，深入了解师生的真实痛点。
    - **实践**: 每个新功能都应产出一份简要的用户调研纪要和痛点清单。

2.  **🎨 梦想家 (Design)**
    - **原则**: 先有蓝图，再有高楼。使用现代设计工具（如 Figma）进行原型设计，将模糊的想法转化为清晰、可视、可交互的界面。
    - **实践**: 任何涉及界面的改动，都应先提供可点击的 Figma 原型，以供团队评审和测试用户流程。

3.  **⚡ 战斗计划 (Plan)**
    - **原则**: 将宏大目标分解为可执行的任务。使用 WBS (工作分解结构) 和敏捷开发方法，将功能开发分解为小的、可管理的 Sprint 任务。
    - **实践**: 平台开发应维护一个公开的 Backlog，清晰地展示每个 Sprint 的任务范围和优先级。

4.  **💰 创业之夜 (Validate)**
    - **原则**: 用数据和用户反馈来验证设计的有效性。每个功能的上线都不是终点，而是数据收集和迭代的开始。
    - **实践**: 为核心功能设计关键数据指标（如：项目创建率、里程碑提交率），并定期复盘。

## 3. MVP 定义方法 (MVP Definition)

在资源有限的情况下，我们采用 **MoSCoW** 方法来确定功能的优先级，确保核心价值的快速交付。

- **Must Have (必须有)**: 构成产品核心闭环的必备功能。如果缺少，整个流程都跑不通。
  - *示例: 项目的创建、提交、查看功能。*
- **Should Have (应该有)**: 能够显著提升用户体验或解决次要痛点的重要功能，但暂时缺少也能运行。
  - *示例: 教师在线预览附件，而不是必须下载。*
- **Could Have (可以有)**: 锦上添花的功能，能带来惊喜，但优先级较低。
  - *示例: 个性化的成就徽章系统。*
- **Won't Have (暂不做)**: 在当前阶段或未来几个版本内明确不做，以保持专注。
  - *示例: 平台内置的即时聊天工具。*

## 4. 设计工具与资源

- **原型与UI设计**:
  - **Figma**: 核心工具，用于高保真原型设计、UI绘制和交互演示。
  - **即时设计**: 备选，作为国内的对标产品。
- **任务与文档管理**:
  - **Notion / 飞书文档**: 用于撰写PRD、整理调研纪要、维护开发任务 Backlog。
- **灵感与素材**:
  - **Unsplash**: 高质量图片素材。
  - **Iconfont**: 矢量图标库。
