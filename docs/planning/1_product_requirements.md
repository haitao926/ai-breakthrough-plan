# 1. 产品需求与任务计划 (PRD)

**版本**: v1.0
**状态**: 进行中

## 1. 平台核心目标 (Core Platform Goals)

本平台旨在将“AI破壁计划”从一个课程体系，升级为支持学生科创项目从“选题-立项-过程-评审-结题-展示”的全生命周期一站式服务平台。平台必须支撑课程设计的核心闭环逻辑：

- **闭环1**: `课程2(产品规划)` 的成果，必须能作为 `课程3(全栈开发)` 的输入。
- **闭环2**: `课程4(算法研究)` 的成果，必须能部署于 `课程5(智能硬件)`。
- **总闭环**: `课程6(综合实践)` 将综合运用前面所有项目的能力与成果。

平台功能的设计必须服务于学生的最终收获，即产出 **6大有形成果**（体感游戏、产品规划、Web应用、研究报告、智能硬件、创业项目）并锻炼其对应的 **6大核心能力**。

---

## 2. 目标用户与核心场景

### 2.1. 目标用户

- **学生**:
  - 作为项目负责人或成员，在平台上完成项目的完整生命周期。
  - 关注点：项目路径清晰、过程可跟踪、成果可沉淀、操作简便。
- **老师**:
  - 作为指导者和管理者，审核立项、追踪进度、评审项目、归档成果。
  - 关注点：统一收集信息、高效管理、便捷评审、数据可追溯。

### 2.2. 关键场景

- **选题与立项**: 学生提交开题报告与附件 → 老师审核通过/驳回。
- **过程管理**: 学生按里程碑提交阶段性成果 → 老师在线查看与反馈 → 学生根据反馈迭代。
- **结题评审**: 学生提交结题报告与完整成果包 → 老师评审并确认归档。
- **成果展示**: 优秀项目进入展示墙，其成果（代码、文档、模型）可被其他同学参考复用。

---

## 3. 功能范围 (Scope)

### 3.1. MVP 范围 (第一阶段核心闭环)

- **项目立项**: 支持创建项目，提交开题表单 (含附件)，记录和流转审核状态。
- **过程管理**: 支持按里程碑提交成果，查看进度，记录老师的反馈。
- **结题归档**: 支持提交结题报告和最终成果包，记录归档状态。
- **基础展示**: 提供项目列表页，并有一个简单的优秀项目展示页。
- **教师面板**: 教师可以按项目/班级筛选查看提交，并下载所有附件。

### 3.2. 后续范围 (第二、三阶段)

- **评分与评审体系**: 引入多评委与详细评分标准。
- **用户与组织体系**: 支持多班级、多学校的组织架构，引入单点登录(SSO)。
- **资源管理**: 经费、设备、场地的申请与管理。
- **Gitea 深度集成**: 在平台内预览代码、查看提交记录。
- **社区与交流**: 项目问答区、全站公告。

## 4. 实施路线与任务计划 (Roadmap)

### 第一阶段：基础建设 (MVP)

- **目标**: 完成数据管理系统升级，跑通项目生命周期核心闭环。
- **任务**:
  1.  **引入数据库**: 从 `jsonl` 迁移到 SQLite，并建立核心数据模型 (用户、项目、提交、反馈)。
  2.  **开发后端核心API**: 实现对项目、提交等实体的增删改查 API。
  3.  **开发前端核心流程页面**:
      - 学生端：创建项目、提交开题/里程碑/结题报告的表单页。
      - 教师端：项目列表、详情页，可查看学生提交并给出文字反馈。

### 第二阶段：核心流程整合

- **目标**: 打通核心的用户和教学流程，让平台真正“可用”。
- **任务**:
  1.  **建立统一用户管理**: 实现平台的用户注册登录，并与 Gitea 账户打通 (SSO)。
  2.  **开发团队管理功能**: 支持学生创建团队、邀请/管理成员。
  3.  **完善在线评审功能**: 教师可在线预览文件（PDF, Markdown），并给出结构化评分。

### 第三阶段：体验优化与系统集成

- **目标**: 提升用户体验，实现系统功能的深度整合。
- **任务**:
  1.  **前端现代化改造 (SPA)**: 使用 Vue 或 React 将前端改造为单页应用，提升流畅度。
  2.  **Gitea 深度集成**: 在项目页内嵌显示代码提交记录、文件预览等。
  3.  **开发通知系统**: 当提交被评价或状态变更时，向用户发送通知。

### 第四阶段：社区生态建设

- **目标**: 提升平台的活跃度和用户的归属感。
- **任务**:
  1.  **强化作品展示墙**: 自动或由教师推荐优秀项目上墙。
  2.  **增加社区与交流功能**: 为每个项目设立问答区，并建立全站公告系统。

---

## 5. 验收标准 (MVP)

- [x] 学生可以成功创建一个项目，并完成开题、至少一次里程碑提交、结题的完整流程。
- [x] 教师可以在管理后台看到学生的所有提交物，并能成功下载所有附件。
- [x] 教师可以对学生的每次提交添加文字反馈。
- [x] 项目的状态（审核中、进行中、已归档等）和里程碑的状态（待提交、已提交、已反馈）能够被正确追踪和显示。
