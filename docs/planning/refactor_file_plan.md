# 文件视角重构方案（Draft）

本文件从“文件结构与目录职责”的角度梳理重构路径，目标是在不破坏现有可用性的前提下，逐步迁移到 Vue 架构。

## 1. 现状问题（文件层面）
- `apps/web` 为静态 HTML/JS 混合，页面逻辑分散，难以复用。
- 业务模块（立项/调研/创新/WBS/提交/看板/审核）没有独立模块边界。
- API 与前端配置分散（API_BASE 硬编码，部署需人工修改）。
- 工具页数据依赖 localStorage，难以与提交/看板形成稳定链路。

## 2. 重构目标（文件结构）
- 保留 `apps/web` 作为可用旧版，新增 `apps/web-vue` 逐步迁移。
- Vue 工程内按“页面 / 模块 / 公共”分层：
  - `src/pages/` 页面入口（workspace/tools/projects/teacher）
  - `src/modules/` 业务模块（inception/implementation/feedback）
  - `src/components/` 可复用组件（进度条/表单/任务卡）
  - `src/api/` 统一 API 客户端与配置读取

## 3. 执行顺序（文件迁移顺序）
1) 新建 `apps/web-vue` 并建立最小运行骨架（已执行）。
2) 先迁移 `workspace` 相关页面（核心闭环），再迁移 `tools`。
3) 将 `auth.js` 的 API_BASE 改为运行时配置，并迁移到 `src/api/client.js`。
4) 将 `tools` 的表单逻辑拆为模块组件，统一数据流。

## 4. 风险控制
- 旧版保持可用，Vue 版本仅在新入口或开发模式下启用。
- 每迁移一个页面，保证“功能对齐 + 数据一致”。

## 5. 下一步（执行）
- 将 workspace 的进度清单与 WBS 预览迁移为 Vue 组件。
- 建立 `src/modules/inception` 目录，统一立项阶段逻辑。
- 完成 API 配置统一（`/config.json`）。
