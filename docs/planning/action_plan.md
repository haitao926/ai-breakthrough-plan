# 执行计划（Action Plan）与 Vue 重构路线

**目标**：先打通“立项—提交—看板—代码交付”的闭环，再以最小风险完成 Vue 重构。计划分为“补全（Fix）”与“增强（Feat）”两类任务，并提供清晰验收标准。

---

## 一、总体策略

1) **先闭环、后重构**：P0/P1/P2 先在现有实现中打通流程，确保教学能跑通。
2) **双轨迁移**：旧版维持可用，新版 Vue 逐步替换关键页面，做到“随时可回滚”。
3) **验收驱动**：每个任务都要有明确的“可验证结果”。

---

## 二、当前不足（摘要）

- **数据闭环不稳**：工具页数据与开题提交/看板任务的衔接不够严格。
- **实施阶段交付不刚性**：代码提交要求缺乏规范化与复用机制。
- **教师反馈弱**：需要“审核—退回—修改—再提交”的状态闭环。

---

## 三、执行清单（Fix / Feat）

### P0 立项与数据闭环（The Data Loop）
**目标**：工具数据能无缝流转到工作台并成功提交。

- [ ] **T01-A (Fix): 工具-工作台数据映射验证**
  - 内容：核对 `charter.html / pre_research.html / innovation.html / wbs.html` 的 LocalStorage Key 与 `workspace.html` 读取逻辑一一对应。
  - 验收：在工具页填写后，工作台“立项完成度”进度条正确跳动，缺失提示准确。

- [ ] **T01-B (Fix): WBS 同步看板修复**
  - 内容：调试 `syncMilestonesFromWbs`，确保提交开题后，WBS 任务写入 `project_milestones`。
  - 验收：提交开题后刷新，看板自动出现 WBS 任务（且不重复）。

- [ ] **T02 (Feat): 开题报告渲染优化**
  - 内容：优化 `buildProposalMarkdown` 输出结构，包含“核心四问、调研结论、创新点、WBS 概览”。
  - 验收：后台查看的开题内容结构清晰、字段完整。

### P1 实施与代码交付（The Code Loop）
**目标**：建立强制代码交付规范，减少重复输入。

- [ ] **T05 (Feat): Gitea 链接格式校验**
  - 内容：对 `codeRepo` 做 http(s)/ssh 格式校验，拒绝无效输入。
  - 验收：输入“没有/不知道”无法提交，提示格式错误。

- [ ] **T06 (Feat): 仓库信息自动复用**
  - 内容：提交表单打开时，自动回填上一次的 `codeRepo`。
  - 验收：后续里程碑无需重复粘贴仓库地址。

- [ ] **T07 (可选增强): Gitea 自动校验**
  - 内容：后端校验仓库存在/commit 是否有效（内网 Gitea）。
  - 验收：无效仓库/commit 时提交失败并提示原因。

### P2 教师反馈闭环（The Feedback Loop）
**目标**：打通“提交-审核-反馈-修改”的状态流。

- [ ] **T08 (Feat): 教师端审核按钮**
  - 内容：老师详情页增加 [通过] / [退回修改]；退回需填写意见。
  - 验收：状态变为 `needs_changes`，并记录反馈。

- [ ] **T09 (Feat): 学生端反馈展示**
  - 内容：workspace 识别 `needs_changes`，醒目展示反馈并允许再提交。
  - 验收：学生可看到老师意见并重新提交。

## 四、Vue 重构路线（分阶段）

### 阶段 0：技术决策（必须先定）
- [ ] 选型：Vue 3 + Vite
- [ ] 路由策略：SPA 或多入口
- [ ] 状态管理：Pinia 或组合式 + localStorage
- [ ] API 封装：保留 `auth.js` 还是新建 client
- [ ] 迁移范围：优先 workspace 或先迁移 tools

### 阶段 1：最小运行架构
- [ ] 创建 `apps/web-vue`（或 `apps/web/src`）
- [ ] 组件化基础布局（Sidebar/Header/Main）
- [ ] API client + project/submission/milestones 数据层

### 阶段 2：P0 功能迁移（与闭环一致）
- [ ] 立项完成度组件（Progress + Checklist）
- [ ] WBS 预览组件
- [ ] Proposal 生成逻辑迁移为 composable
- [ ] Milestone 表单组件化

### 阶段 3：工具页迁移
- [ ] Innovation → WBS → Pre-research → Literature → Charter

### 阶段 4：教师端迁移
- [ ] 评审与退回机制 UI
- [ ] 反馈展示与重提交流程

- **教师反馈**：老师退回后学生可看到反馈并重提。
