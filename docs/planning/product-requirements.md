# 学生科创项目平台 - 产品需求文档（PRD）

## 1. 背景与目标
- 现状：现有平台偏“资料展示/作业提交”，缺少科创项目全生命周期管理。
- 目标：覆盖学生科创项目从“选题-立项-过程-评审-结题-展示”的全流程闭环。
- 价值：
  - 学生：项目路径清晰、过程可跟踪、成果可沉淀。
  - 老师：统一收集、评审与归档，提高管理效率。
  - 平台：打通数据、整合系统、优化流程。

## 2. 目标用户与角色
- 学生：选题、提交开题与里程碑成果、结题归档。
- 老师：审核立项、查看进度、评审结题、成果归档。
- 备注：当前阶段仅实现“学生/老师”两类角色，其他角色后续扩展。

## 3. 关键场景
- 选题与立项：学生提交开题报告与附件 → 老师审核通过/驳回。
- 过程管理：里程碑提交 → 老师查看与反馈 → 学生迭代。
- 结题评审：结题报告 + 成果包提交 → 老师确认归档。
- 展示沉淀：优秀项目展示墙，成果可复用。

## 4. 范围与非范围
### MVP 范围（全生命周期最小闭环）
- 项目立项：开题表单 + 附件 + 审核状态。
- 过程管理：里程碑提交 + 进度查看 + 反馈记录。
- 结题归档：结题报告 + 成果包 + 归档状态。
- 展示入口：项目列表与优秀展示（基础版）。

### 非 MVP（后续）
- 评审评分体系、评委角色
- 账号与组织体系（多班级/多学校）
- 经费/设备/场地管理
- 竞赛报名与证书管理
- 前端 SPA 化与 Gitea 深度集成
- 社区与交流功能

## 5. 核心功能模块
- 项目立项：开题提交、审核、状态流转。
- 里程碑管理：阶段成果提交与反馈。
- 结题与归档：结题报告、成果附件、归档记录。
- 项目展示：项目列表与成果展示墙（基础版）。
- 老师面板：按项目/班级筛选、下载、导出（可选）。

## 6. 关键流程与状态
- 项目状态：草稿 → 已提交 → 审核中 → 通过/驳回 → 进行中 → 中期评审 → 结题待审 → 已归档
- 里程碑状态：待提交 → 已提交 → 已反馈

## 6.1 阶段模板（融合版）
- 开题（闸门1）：问题/目标/范围/技术路线/计划/成员 + 附件
- 里程碑1（功能一）：需求调研与可行性、风险清单、功能一范围
- 里程碑2（功能二）：方案设计与原型、架构图/关键路径
- 中期评审（闸门2）：进度对比、演示链接、问题与调整
- 里程碑3（项目集成）：联调/测试、MVP 验证、反馈记录
- 结题评审（闸门3）：成果包、演示、技术总结、反思与展望
- 展示/归档（可选）：海报/视频/可复用资源
（详见 `docs/planning/stage-template.md`）

## 7. 数据与指标
- 立项通过率、结题率、按项目分布
- 里程碑按时率、反馈次数

## 8. 非功能需求
- 安全：基础上传校验与目录隔离。
- 性能：班级并发稳定上传与下载。
- 可靠性：提交记录可恢复（日志/文件）。
- 部署：本地/局域网可用。

## 9. 验收标准（MVP）
- 项目可完成立项 → 过程提交 → 结题归档完整闭环。
- 老师可查看所有阶段记录，并可下载附件。
- 项目状态与里程碑状态可追踪。

## 10. 风险与依赖
- 本地存储容量与备份策略需要提前评估。

## 11. 实施路线（对齐 PLATFORM_IMPROVEMENT_PLAN）
1. 数据管理系统升级：从文件日志迁移到数据库，建立核心数据模型。
2. 核心流程整合：立项-过程-结题闭环 + 教师评价反馈。
3. 体验优化与系统集成：前端 SPA 化，逐步接入 Gitea 能力。
4. 社区生态建设：作品墙、讨论区与公告系统。
