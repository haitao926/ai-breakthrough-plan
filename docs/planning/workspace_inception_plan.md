# 立项阶段体验与流程梳理方案（草案）

> 目的：以“梳理过程=自然生成开题”的方式，引导学生走完**科研路径 + 产品路径**，自动产出 WBS，并以“报告结构”作为过程指导而非最终目的。

## 1. 背景与问题
- 现有流程割裂：工具页内（如立项书）填写的内容停留在本地，提交与数据库脱节。
- 学生体验是“填表 + 上传”，而不是“被引导完成项目路径”。
- 教学目标是：让学生理解并走完**调研 → 方案 → 实施 → 验证 → 表达**的完整路径。

## 2. 核心目标（对齐你的需求）
- **开题即立项**：学生完成立项梳理后，系统自然完成开题提交，不再让学生重复填报。
- **创新点必答**：所有项目必须明确创新点，并说明其验证方式。
- **调研必做**：无论项目类型，必须包含前期调研（文献/问卷/访谈等）。
- **双路径合流**：同时涵盖科研路径与产品路径，不做二选一。
- **WBS 自动生成是关键**：学生不手写任务，系统生成基础 WBS，学生只微调。
- **报告生成是手段**：报告模板用于引导学生完成流程，并将过程结构化。
- **交付物差异驱动**：项目类型差异主要体现在最终交付物，而不是“工程 vs 研究”的标签。

## 3. 立项阶段体验（学生视角）
学生并不直接“写报告”，而是完成一组**结构化梳理卡片**：

### Step A：项目骨架（最小输入）
- 项目名称
- 面向谁 / 解决什么问题
- 一句话目标
- 团队成员

### Step B：调研路径（必做）
- 选择调研方式（文献 / 问卷 / 访谈 / 观察，可多选）
- 调研要点与预期结论

### Step C：创新点（必答）
- 现有方案是什么？
- 你的不同在哪里？（新方法 / 新场景 / 新组合 / 新效率）
- 你打算如何验证创新？

### Step D：方法与任务拆解
- 我的方法 / 技术路线（研究路线 or 解决方案）
- 任务一 / 实验一（目标 + 方法 + 输出）
- 任务二 / 实验二（目标 + 方法 + 输出）

### Step E：系统呈现与验证
- 系统呈现（模块 / 原型 / 结构图）
- 实验验证与结果分析
- 讨论与展望

> 以上步骤即为“开题报告”结构的**过程化拆解**。

## 4. 报告结构（指导用，不是目的）
报告结构是“流程地图”，用于帮助学生拆解任务：

1. 背景与意义
2. 研究方法
3. 创新点
4. 我的方法
5. 任务一 / 实验一（功能实现）
6. 任务二 / 实验二（知识学习与功能实现）
7. 系统呈现
8. 实验验证与结果分析
9. 讨论与展望

> 这些章节将作为引导模块，系统可自动生成报告预览，但重点是“过程完成度”。

## 5. WBS 自动生成规则（核心机制）
### 基础 WBS（一级固定）
- 调研与问题定义
- 方案与设计
- 实施与验证
- 成果表达

### 自动扩展（二级任务）
- 调研路径 → 文献检索 / 问卷设计 / 数据整理 / 结论输出
- 创新点 → 竞品对比 / 创新点描述 / 创新验证方式
- 任务一/二 → 自动拆分为“准备-实施-输出”
- 系统呈现 → 原型设计 / 界面搭建 / 架构图整理
- 验证结果 → 测试/实验记录 / 数据分析 / 结论总结

### 交付物驱动扩展
- 研究型交付物：报告 + 过程图片/数据
  - 报告撰写与排版
  - 过程图片/实验记录整理
- 工程型交付物：演示视频 + 代码/原型
  - 演示脚本
  - 录制与剪辑
  - 代码整理与归档

> 结果：学生只需微调，而不是从 0 列任务。

## 6. 完成度与提交机制
- 系统根据关键模块完成度（调研/创新/方法/任务/验证）计算“就绪度”。
- 达标后提示“具备开题条件”，进入“确认提交”视图（仅预览，不再填表）。
- 提交时自动生成：
  - 开题报告正文（结构化内容拼接）
  - WBS 任务列表（存入提交详情或里程碑表）

## 7. 关键补充机制（增强版）
### 7.1 可行性自检（Feasibility Check）
- 目的：避免“眼高手低”，在提交前自查资源与时间。
- 建议位置：Step D（方法与任务拆解）后或提交前确认页。
- 内容建议：
  - 需要的硬件/资源（如：树莓派、摄像头、3D 打印机）
  - 预计投入时间（根据任务数粗算：任务数 × 每周可用小时数）
  - 自检勾选：资源可获得、时间可完成（作为提交门槛）

### 7.2 WBS 与 Kanban 无缝连接
- 目的：让 WBS 成为“开工即有任务”的实际行动清单。
- 建议：
  - 提交立项时，把 WBS 写入项目的里程碑/任务表。
  - 学生首次进入工作台的看板即呈现任务清单，避免空白。
- 价值：形成“开工暗示”，增强执行感。

### 7.3 创新点 AI 评审（Unique Selling Point）
- 目的：帮助学生“自证创新”，避免空泛表述。
- 交互建议：
  - 在创新点模块增加“AI 评审”按钮。
  - Prompt 方向：以严厉评委视角指出是否真创新、是否已有类似产品。
- 作用：在提交前让学生主动修正创新点表达与验证路径。

### 7.4 教师端立项批注
- 目的：让老师快速关注创新点与可行性。
- 建议：
  - 审核页高亮“创新点 + 验证方式”字段。
  - 允许老师对 WBS 做修改建议，并将状态退回为 needs_changes。

## 8. 数据映射（概念层）
- 梳理数据 → 结构化字段（details）
- 报告正文 → Markdown 文本（content）
- WBS → JSON 任务树 / 里程碑清单

## 9. 教学价值对齐
- 通过“流程化引导”，帮助学生走完科研与产品路径。
- 强制完成调研与创新点反思。
- 通过 WBS 形成可执行任务计划，避免空泛描述。
