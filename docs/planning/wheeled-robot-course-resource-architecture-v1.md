# 轮式机器人课程资源架构 v1

## 1. 目标与边界

本方案用于将“轮式机器人 18 课时课程”建设为可复用、可分发、可持续迭代的课程资源体系。

目标不是只产出教案文本，而是建立一套可直接落地到平台的数据与资源结构。

边界：

- 聚焦课程资源架构，不展开具体每一课全文教案
- 默认以当前仓库平台为主线进行资源编排
- 同时提供 STEM LAB / XEDU / 互动实验分支映射策略

## 2. 设计原则

1. 教学优先，格式其次
- 先稳定课程能力递进，再映射到不同平台格式。

2. 一次设计，多端分发
- 先形成平台无关母版，再分支输出到不同平台。

3. 课程结构与课堂流程分离
- 课程层/模块层/课时层管理“教什么”。
- phase 层管理“这 60 分钟怎么推进”。

4. 每课必须有知识点与证据
- 每节课至少包含：核心问题、目标、知识点、产出、评价线索。

5. 先母版后打包
- 当前平台作为主创作源，STEM LAB 和 XEDU 作为后置交付分支。

## 3. 课程母版模型

### 3.1 五层资源模型

1. 课程层（Course）
- 课程定位、受众、节奏、总目标、能力地图。

2. 模块层（Module）
- 将 18 课时按能力递进分组，定义模块目标和里程碑。

3. 课时层（Lesson Contract）
- 定义单课教学契约：本质问题、目标、知识点、产出、误区、评价。

4. 课堂流程层（Phase）
- 导入、讲解、演示、实操、复盘等阶段化推进。

5. 资源层（Resource）
- 教师手册、学生任务单、接线图、结构图、示例代码、记录表、评价表。

### 3.2 Lesson Contract（建议标准字段）

每节课统一具备以下字段（可存入 lesson JSON 顶层）：

- `moduleId`
- `essentialQuestion`
- `learningObjectives`
- `knowledgePoints`
- `equipment`
- `classroomTasks`
- `deliverables`
- `commonMisconceptions`
- `assessmentCriteria`
- `homework`
- `lessonResources`

说明：
- `phases` 继续保留用于 study 页面推进。
- 教学契约字段与 `phases` 解耦，避免“只有流程，没有课程”。

## 4. 18 课时模块地图（v1）

### 模块 M1：从能动到可控（L1-L6）

核心能力：
- 理解轮式机器人结构与差速运动
- 完成供电、连线、执行器控制
- 建立输入读取与脉冲测量基础

建议课次：
- L1 轮式机器人的结构与运动原理
- L2 供电、连线与安全上电
- L3 电机驱动与正反转控制
- L4 基础运动：直行、后退、停止
- L5 按钮输入：电平判断与跳变判断
- L6 编码器输入：脉冲、边沿与计数

### 模块 M2：从可控到走得准（L7-L12）

核心能力：
- 理解开环误差
- 建立调速、测速和基础反馈修正能力
- 实现定距离与稳定运动

建议课次：
- L7 编码器测速
- L8 PWM 调速
- L9 开环误差观测与分析
- L10 编码器辅助直行
- L11 差速转向与动作参数化
- L12 定距离行走与停车

### 模块 M3：从走得准到可任务化（L13-L16）

核心能力：
- 引入环境感知
- 构建“感知-判断-动作”任务闭环
- 完成多模块联调

建议课次：
- L13 超声波避障
- L14 巡线传感器读取与阈值校准
- L15 巡线控制策略
- L16 多模块任务整合与联调

### 模块 M4：从任务化到工程展示（L17-L18）

核心能力：
- 工程优化与稳定性提升
- 展示表达与复盘沉淀

建议课次：
- L17 作品优化与展示准备
- L18 挑战赛与课程复盘

## 5. 当前平台落地方案（主线）

### 5.1 文件结构

建议继续使用现有模式：

- `content/courses/robotics-club/course.json`
- `content/materials/robotics-club/lessons/lesson1.json` ... `lesson18.json`
- `content/materials/robotics-club/TEACHING_MANUAL.md`
- `content/materials/robotics-club/课程导学.md`
- `content/materials/robotics-club/学生任务单.md`

### 5.2 落地策略

1. `course.json`
- 增加 18 课时节奏描述与模块化定位。

2. `lessons/*.json`
- 保留 `phases` 可渲染结构。
- 增加 lesson contract 顶层字段（知识点、误区、评价等）。

3. 教师手册
- 从摘要版升级为模块化执行手册：
  - 课前准备
  - 授课要点
  - 常见故障树
  - 评价口径

4. 学生任务单
- 从通用模板升级为按模块递进任务卡与记录表。

## 6. 分平台输出策略

### 6.1 STEM LAB 分支

用途：
- 需要 LMS 导入包时使用。

映射方式：
- 课程母版 -> `unit.json`
- lesson contract + phases -> `lesson.json`
- 图示、数据、活动模板 -> `assets`

建议：
- 先维护当前平台母版，再做导出，避免双份源数据漂移。

### 6.2 XEDU 分支

用途：
- 对外分发、归档、交付时使用。

映射方式：
- 教师/学生文档 -> materials 目录
- 实验脚手架与样例代码 -> lab/notebooks/data 目录
- 课程说明与运行指南 -> README

建议：
- 作为发布态结构，不作为课程设计主编辑结构。

### 6.3 互动实验分支

用途：
- 适合编码器、调速、巡线等需要“先体验后编码”的课次。

映射方式：
- 单课新增 `task_spec.json`
- 生成 `demo.html + main.ipynb + scaffold scripts`

建议：
- 只在关键课次使用，不替代整门课主资源体系。

## 7. 课程资源融合策略

建议采用“融合创建，分支交付”：

1. 创建阶段融合
- 课程架构逻辑（UbD / 能力递进）
- 单课材料逻辑（课堂活动与评价）
- 工程实验逻辑（互动体验与代码实践）

2. 交付阶段分支
- 当前平台主线
- STEM LAB 导入支线
- XEDU 打包支线
- 互动实验增强支线

这样可以避免：
- 平台格式反向绑架教学设计
- 多平台同时维护导致课程内容不一致

## 8. 实施路线（建议）

### 阶段 A：母版定型（先做）

1. 定稿模块地图（M1-M4）
2. 定稿 lesson contract 字段规范
3. 做 L1 完整样板（含知识点、误区、评价、phases）

### 阶段 B：批量扩展

1. 完成 L2-L18 lesson contract
2. 再写每课 phases
3. 升级教师手册与学生任务单

### 阶段 C：分平台输出

1. 输出当前平台完整版本（主）
2. 选择性导出 STEM LAB 包
3. 选择性导出 XEDU 包

## 9. 验收标准（v1）

满足以下条件即认为“架构完成”：

1. 18 课时已按模块组织并能解释能力递进逻辑
2. 每节课具备知识点字段，不是纯活动清单
3. lesson contract 与 `phases` 明确分层
4. 教师材料与学生材料对齐课时结构
5. 已定义当前平台与至少一个外部平台的映射规则
